# TikLive Web — веб-версия, как у TikFinity

Стример открывает сайт, регистрируется по e-mail и сразу работает в браузере. Ничего устанавливать не нужно: подключение к TikTok LIVE держит сервер, а оверлеи — это личные ссылки, которые добавляются в OBS или TikTok LIVE Studio.

```
браузер стримера ──(панель /app, сессия)──▶  TikLive Web  ──▶ TikTok LIVE (по нику)
OBS / LIVE Studio ──(/o/<токен>/?w=alerts)──▶  (сервер)    ──▶ Claude (ИИ), Lemon Squeezy (подписка)
```

## Что умеет

- **Аккаунты.** Регистрация и вход по e-mail. Пароли хранятся только в виде хеша (scrypt), сессия живёт в защищённой cookie 30 дней.
- **У каждого пользователя своё пространство:** свои правила, цели, очки зрителей, статистика и подключение к TikTok. Данные одного стримера не видны другому.
- **Личные ссылки на оверлеи** `/o/<токен>/?w=…`. Работают в OBS без входа в аккаунт. Если ссылка утекла, кнопка «Сменить ссылки оверлеев» мгновенно отключает старые.
- **Эфир не прерывается.** Подключение к TikTok держит сервер, даже когда вкладка браузера закрыта. После перезапуска сервера подключение восстанавливается само.
- **ИИ-ответы** идут через ключ Anthropic сервера. Модель задаёт сервер, а не пользователь. Лимиты: 500 ответов в месяц для Pro и 100 на пробный период.
- **Подписка Pro включается сама.** 7 дней бесплатно с момента регистрации, дальше $8 в месяц. Кнопка «Оформить подписку» ведёт на оплату Lemon Squeezy с уже подставленными e-mail и номером аккаунта. После оплаты Lemon Squeezy присылает на сервер подписанное уведомление, и Pro включается в течение нескольких секунд, без ключей. Отмена, продление, проблемы с картой и окончание подписки отслеживаются так же. Отменённая подписка работает до конца оплаченного месяца.
- **Вход через TikTok** («Продолжить с TikTok»). TikTok не передаёт e-mail, поэтому аккаунт определяется по TikTok ID, а ник стримера подставляется в поле подключения эфира сам. Если у стримера уже есть аккаунт по e-mail, в «Настройках» есть кнопка «Привязать TikTok». Один TikTok нельзя привязать к двум аккаунтам. Аккаунтам без e-mail пароль не нужен.
- **Вход через Google** («Продолжить с Google»). Новый пользователь получает аккаунт без пароля, почту подтверждать не нужно — это уже сделал Google. Если аккаунт с тем же e-mail уже есть, Google к нему привязывается. Пароль можно задать позже в настройках, чтобы входить и по e-mail.
- **Подтверждение e-mail при регистрации.** После регистрации приходит письмо со ссылкой (действует 48 часов, одноразовая). До подтверждения можно всё настраивать, пользоваться симулятором и оверлеями. Подключение эфира TikTok и ИИ включаются только после подтверждения: они тратят ресурсы сервера (лимиты Euler Stream и деньги на Claude). В панели висит плашка с кнопкой «Отправить письмо ещё раз» (не чаще 3 раз в час). Сброс пароля по почте тоже считается подтверждением. Если почта на сервере не настроена, подтверждение выключено и аккаунты активны сразу.
- **Восстановление пароля по e-mail.** Ссылка одноразовая и действует 1 час. После сброса все старые сессии завершаются. Ответ на запрос одинаковый для любых адресов, поэтому по нему нельзя узнать, зарегистрирован ли e-mail. Сменить пароль можно и в настройках.
- **Защита:** от CSRF (изменения принимаются только в формате JSON, cookie с SameSite=Lax) и от подбора пароля (10 попыток за 15 минут с одного IP).

**Только в приложении для ПК:** нажатие клавиш в играх и прямое управление OBS. Сервер физически не может нажимать клавиши на компьютере стримера. Остальное работает в браузере.

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `SESSION_SECRET` | да | случайная строка ≥ 32 символов: `openssl rand -hex 32`. После запуска не меняйте |
| `SIGN_API_KEY` | очень желательно | ключ Euler Stream для подключения к TikTok. Без него сервер быстро упрётся в лимиты подключений |
| `ANTHROPIC_API_KEY` | для ИИ | ключ Claude. Без него вкладка ИИ сообщает, что ИИ не подключён |
| `LS_STORE_ID`, `LS_PRODUCT_ID`, `CHECKOUT_URL` | для продаж | данные магазина Lemon Squeezy |
| `LS_WEBHOOK_SECRET` | для автоактивации Pro | Signing secret вебхука Lemon Squeezy (см. ниже) |
| `PUBLIC_URL` | для писем | адрес сайта, например `https://app.tiklive.com`. Из него строятся ссылки в письмах |
| `RESEND_API_KEY`, `MAIL_FROM` | для писем | ключ resend.com и адрес отправителя, например `TikLive <no-reply@tiklive.com>` |
| `MAIL_DEV_LOG=1` | | только для разработки: печатать письма в лог вместо отправки |
| `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` | для входа через TikTok | ключи приложения из TikTok for Developers (см. ниже). Нужен и `PUBLIC_URL` |
| `TIKTOK_SCOPES` | | по умолчанию `user.info.basic,user.info.profile` (`profile` даёт @ник). Если `profile` не одобрили — укажите `user.info.basic` |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | для входа через Google | OAuth-клиент из Google Cloud Console (см. ниже). Нужен и `PUBLIC_URL` |
| `AI_MODEL`, `AI_EFFORT`, `PRO_MONTHLY_LIMIT`, `TRIAL_LIMIT` | | `claude-opus-5-5`, `low`, 500, 100 |
| `DATA_DIR` | | где хранить данные (`/data` в Docker) — нужен постоянный диск |
| `TRUST_PROXY=1` | за прокси | доверять заголовкам `X-Forwarded-*` (Render, Railway, Fly, nginx) |
| `SECURE_COOKIES=1` | при HTTPS без прокси | ставить cookie только по HTTPS |
| `ALLOW_SIGNUP=0` | | закрыть регистрацию (например, на время бета-теста) |
| `PORT` | | 8080 |

## Запуск

Локально:
```bash
SESSION_SECRET=$(openssl rand -hex 32) npm run web
# откройте http://localhost:8080
```

Docker на VPS (за Caddy или nginx с HTTPS):
```bash
docker build -f hosted/Dockerfile -t tiklive-web .
docker run -d --restart=always -p 8080:8080 -v tiklive-web:/data \
  -e SESSION_SECRET=... -e SIGN_API_KEY=... -e ANTHROPIC_API_KEY=... \
  -e LS_STORE_ID=... -e LS_PRODUCT_ID=... -e CHECKOUT_URL=... tiklive-web
```

Render или Railway: Web Service из репозитория, Dockerfile — `hosted/Dockerfile`, постоянный диск в `/data`, переменные из таблицы.

Сервер должен работать **постоянно**. Бесплатные тарифы, которые «засыпают» без трафика, не подходят: эфиры стримеров будут обрываться.

## Подключение оплаты и почты

**Автоактивация Pro (Lemon Squeezy):**
1. В Lemon Squeezy: **Settings → Webhooks → +**. URL: `https://ваш-сайт/webhooks/lemonsqueezy`. Придумайте **Signing secret** и отметьте события `subscription_created`, `subscription_updated`, `subscription_cancelled`, `subscription_resumed`, `subscription_expired`, `subscription_paused`, `subscription_unpaused`.
2. Тот же secret укажите в `LS_WEBHOOK_SECRET`, ссылку на оплату продукта — в `CHECKOUT_URL`.
3. Проверьте в Test mode: зарегистрируйтесь, нажмите «Оформить подписку», оплатите тестовой картой. Вкладка Pro должна показать «Pro активен». В логе сервера появится строка `[billing] subscription_created: user … → active`.

Если человек оплатил с другого e-mail, это не страшно: аккаунт определяется по номеру из ссылки на оплату. Если оплата прошла вне сайта, сервер ищет аккаунт по e-mail покупателя. Ввод ключа вручную остаётся запасным вариантом («У меня есть ключ лицензии»).

**Письма (Resend):** зарегистрируйтесь на resend.com, подтвердите свой домен (DNS-записи из их панели) и создайте API-ключ. Задайте `RESEND_API_KEY`, `MAIL_FROM` и `PUBLIC_URL`. Без них восстановление пароля честно отвечает «не настроено».

**Вход через TikTok:**
1. developers.tiktok.com → **Manage apps → Connect an app**. Заполните название, иконку, категорию, описание и ссылки на условия и политику (`docs/terms.html`, `docs/privacy.html`).
2. Добавьте продукт **Login Kit** и платформу **Web**. В **Redirect URI** укажите `https://ваш-сайт/auth/tiktok/callback` (должен совпадать с `PUBLIC_URL`). Домен сайта нужно подтвердить в разделе URL properties.
3. Scopes: `user.info.basic`, а для автоподстановки ника — `user.info.profile`.
4. Отправьте приложение на проверку (**Submit for review**). До одобрения вход работает только для аккаунтов, добавленных в **Sandbox** как тестовые. Проверка обычно занимает от нескольких дней до пары недель. TikTok может попросить видео с демонстрацией входа.
5. Скопируйте **Client key** и **Client secret** в `TIKTOK_CLIENT_KEY` и `TIKTOK_CLIENT_SECRET`. На странице входа появится кнопка «Продолжить с TikTok».

**Вход через Google:**
1. Откройте console.cloud.google.com → создайте проект → **APIs & Services → OAuth consent screen**. Тип **External**. Укажите название TikLive Studio, e-mail поддержки и ссылки на условия и политику с вашего сайта (`docs/terms.html`, `docs/privacy.html`). Scopes: `openid`, `email`, `profile`.
2. **Credentials → Create credentials → OAuth client ID**, тип **Web application**. В **Authorized redirect URIs** добавьте `https://ваш-сайт/auth/google/callback` — адрес должен совпадать с `PUBLIC_URL` до символа.
3. Скопируйте Client ID и Client secret в `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` и перезапустите сервер. На странице входа появится кнопка «Продолжить с Google».
4. Пока приложение в статусе **Testing**, войти могут только тестовые пользователи, добавленные на экране согласия. Для всех нажмите **Publish app**. Для scopes `openid`/`email`/`profile` проверка Google обычно не требуется.

## Масштаб и стоимость

- Один процесс держит всех пользователей. Неактивные пространства выгружаются из памяти через 30 минут. Ориентир: сотни одновременных эфиров на VPS с 2 ГБ памяти — это оценка, под нагрузкой не проверялась. Для тысяч эфиров нужно несколько серверов и балансировка по пользователям — это следующий этап.
- Главные расходы: VPS (от ~$6 в месяц), Euler Stream (по их тарифу — зависит от числа подключений) и Claude (около $3 в месяц на активного Pro-пользователя при лимите 500 ответов).
